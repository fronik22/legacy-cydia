# Power Logger1.0.0

Installable native recorder + PreferenceLoader pane for jailbroken armv7 iOS6. No Substrate injection is needed for the recorder. Default OFF; Settings > Power Logger > Recording enables it. OFF leaves the one small daemon dormant with no sample timer; it does not unload the process. It works without a cable. No wake lock, Wi-Fi reset, VPN toggle, Internet probes or background app hook.

Records every15/30/60seconds while awake: battery charge/capacity, signed InstantAmperage, voltage, net battery watts, temperature, charger flag, cycle count; all visible processes' CPU delta/RSS/thread/context-switch counters; per-core total CPU; PowerVR3D load; physical/tunnel byte counters/rates; available brightness setting/raw display power state; Amnezia state/counters/retry/error. Unsupported values are null/read_error, not zero. No URLs, VPN profile, packet contents or command-line arguments are collected.

Log path: /var/mobile/Library/Logs/LegacyPower/samples.jsonl plus .1… .7. Each file<=4MiB, at most32MiB total JSONL. Oldest data expires automatically. status.json is a small Settings summary. Root owns the non-writable-by-mobile log directory; root/mobile can read logs. Uninstall preserves recordings/preferences, stops/removes only this daemon and pane. No respring or reboot needed.

Experiment labels create separate sessions on change: unlabelled, video-vpn-on/off, idle-vpn-on/off. Labels are user annotations, not claims that playback or VPN state was changed. Actual Amnezia state is also logged. Enabling or changing interval resets delta baselines; first CPU/rate values are null.

CPU:100% means one fully occupied core; a process can reach200% on dual-core A5. CPU counters use Mach absolute ticks, not a guessed nanosecond unit; verified with a native own-process busy test. Names+PID+start time protect against PID reuse. kernel_task includes idle-thread accounting on this OS, so its raw CPU totals are retained but excluded from load ranking; use host CPU cores for total kernel/system load. CPU/load is NOT per-app watts. GPU3D is NOT the dedicated H.264 decoder. Current is net flow into/out of battery; positive charging current is NOT device power. Derived discharge watts are null whenever external power is connected or current is unavailable/nonnegative. Temperature/charge units are verified on iPad2's IOPMPowerSource PMU; new hardware needs validation.

USB charging contaminates drain measurements. For a useful recording, unplug, keep the same brightness/video/quality and record at least10–15min. If video needs VPN, compare playback versus pauses first. A cached local copy of identical video bytes is a better later way to separate decoder/display cost from Wi-Fi/VPN cost. A different video or idle-only comparison cannot quantify VPN overhead by itself. Let the device sleep normally; no timer forces wake from suspended sleep. Gaps are logged via elapsed monotonic time and reported; instantaneous current snapshots do not integrate energy across sleep or charging transitions.

Copy logs to Mac and run python3 analyze.py samples.jsonl samples.jsonl.1 ... . It groups sessions, reports drain only for >=10min unplugged traces, CPU-time ranking, and candidate high load/temperature/gaps. Signals require interpretation; no automatic killing, throttling or network repair. Samples and status include process/app identifiers: inspect before sharing.

Build: python3 build.py; python3 package.py. Uses the existing external iOS9.3 SDK, old-dpkg-compatible armv7 link sysroot and ldid paths in build.py; override IOS_SDK, IOS_STUB and IOS_LDID on another Mac. These SDK files are not redistributed. Host checks: compile/run test_math_store.c; python3 test_analyze.py. Native diagnostics --once and --self-cpu-test do not start persistent recording. Root launchd job is installed for boot; an unsupervised --daemonize fallback supports legacy SSH launchctl failure. Reboot supervision is not yet validated.

Reuse/provenance: older own VPNBench experiment in /Users/mak/Documents/Codex/2026-07-01/new-chat/work/vpnbench supplied the battery/network experiment concept; this version replaces ps/shell polling and adds signed-current handling, real process deltas, Settings, bounds and tests. Own PerfOverlay preference-pane/build/package patterns reused. XNU2050 public proc_taskinfo ABI and time units consulted at https://github.com/apple-oss-distributions/xnu/blob/xnu-2050.18.24/bsd/sys/proc_info.h and osfmk/kern/bsd_kern.c. Native OS framework headers remain external inputs. New implementation is original local project code.

Existing alternatives considered: CocoaTop's 32bit branch supports iOS6 process viewing; DetailedBatteryUsage explicitly requires iOS8/9. They do not replace this requested switchable contextual trace. No third-party monitoring app installed.
