# Amnezia6 1.1.0 — installed result, 2026-10-26

## Result
Installed on the known iPad2,2 / iOS6.1.3 target using guarded explicit-UDID USB SSH. Final app and daemon hashes match the release build. Original941-byte configuration is byte-for-byte unchanged after tests. The existing server migrated into one saved profile; selected profile and VPN OFF state are preserved. No firmware, jailbreak, router, unrelated service or logger changes.

## Features
- Native **Серверы** button on the home screen. Add, name/rename, edit, select and delete inactive profiles. Selection survives app restarts; active VPN switches through serialized stop/save/start, OFF stays OFF. Editing the active configuration uses the same transaction. An unreachable remote server keeps the chosen profile and existing bounded retry behavior, rather than silently selecting another server. Local write/control-command failures roll back.
- **Серверы → +**: clipboard, file, QR via camera photo, saved QR image, manual text. Plain WG/AWG.conf, vpn://, .vpn and supported Amnezia JSON bundles share one validator and open an editable draft before Save. External imports never auto-connect.
- Legacy file import supports Open In registration and an in-app browser (Documents/Amnezia6, Inbox and Downloads). File/URL handlers and the actual browser-to-editor flow were exercised.
- ContentPaddingAddition supports single values and ranges0–65535 with bounded selection and tracked UDP-window/MTU capacity. Receiving authenticated cookie challenges stores a120-second cookie and generates MAC2 on subsequent normal/rekey retries. Invalid, truncated, stale, mismatched-index and duplicate challenges are rejected. Challenges do not cause an immediate resend flood; existing retry deadlines remain authoritative. DisableCookies does not suppress incoming challenges.
- Existing connection-duration/rekey fix and resolved server IP:port display retained.

## Decisions and reasons
1. Keep the existing native C/Monocypher engine. It already runs on armv7/iOS4–6; no Go runtime or replacement crypto dependency is needed. Padding behavior is adapted from pinned Senko4.1.1; cookie semantics from MIT-licensed upstream WireGuard/AmneziaWG. Existing primitives are checked against an independently generated libsodium XChaCha20Poly1305 cookie vector.
2. Use one private atomic XML plist for profile snapshots, retaining the daemon’s existing flat active-config interface. Directory0700, both files0600/mobile. This preserves existing control/routing behavior and rollback. Startup reconciles an interrupted two-file update by preserving an unmatched active configuration as another profile, keeping both versions. Metadata reads use a short lock separate from serialized control operations, so the UI does not wait for IPC/network delays. Changing an active selection requires a responsive daemon so an unknown live tunnel is not silently replaced.
3. Use existing portable quirc and native camera/photo pickers. Modern document/QR APIs are unavailable on iOS4–6. Photo capture plus decode satisfies QR import without a continuous background scanner or Location Services requirement. No new periodic background work was added.
4. Validate before storage/use, bound imported/decompressed text, reject malformed profiles, overlapping header ranges, oversized packet prefixes/junk, NUL/overlong lines and multiple peers. Each saved profile represents one server/peer. No imported text is executed as shell commands.

## Rejected diagnostic attempts
- Initial UI harness touched an editor before its deferred view loaded: nil controls caused false-positive import checks, failed layout and a Save timeout. Corrected the harness to require loaded controls and wait for navigation; all actual UI cases then passed. No application fix was inferred from that failure. Raw attempt1 retained locally.
- Live rekey/data checks succeeded, but a later app-injected switch-back request timed out after auto-lock/suspension. Cleanup restored original config/store/OFF, verified against backups. Harness now wakes/foregrounds the app and resolves its current PID before each injection; subsequent two-way switching passed. This was a diagnostic scheduling failure, not proof of a VPN reconnect bug.

## Limits
- iOS4.3 deployment build succeeds; fresh physical hardware validation in this task is iOS6.1.3 only. No new iOS4/5 device was available.
- Camera UI opens and the same image callback/decoder/import pipeline is verified with fixtures. Optical capture of a physical QR was not tested. Layout is verified by native frame changes; physical device rotation was not forced.
- The real server was not deliberately flooded/put under DoS load to force cookie replies. Cookie handling is validated against independent fixtures and negative cases on the device, not a forced production server challenge.
- IPv4 full tunnel; no kill switch; Jc<=128,2048-byte datagram bounds and MTU/prefix limits retained. Imports max768KiB, decoded supported bundles max512KiB, plain configuration max128KiB, store max4MiB. This is not exhaustive upstream AWG conformance or a complete security audit. No battery optimization or long video-throughput comparison in this task.
